# JK Story Virtual 3D 핵심 운영팀

상태: 시험운영 설계안 (2026-09-27). 아래 직책은 업무 책임을 구분하기 위한 명칭입니다. 현재 3D 화면의 캐릭터와 업무판은 시험 배치이며, AI 계정 간 자동 전달이나 실제 업무 실행은 아직 연결되지 않았습니다.

## 지휘와 접수

대표 → 전담비서 → 핵심 운영팀(Codex·Claude Code·Hermes) → 전담비서 → 대표 순서로 업무를 접수·보고합니다. 전담비서는 대표의 단일 접점이며, 중요한 결정의 최종 책임자는 대표입니다. 각 업무에는 한 명의 주담당과 검토자를 지정합니다.

| 직책 | 주된 책임 | 대표에게 보여줄 결과 | 경계 |
| --- | --- | --- | --- |
| 전담비서 (업무 접수·조율) | 대표 지시 기록, 목적·기한·센터·관련 화주사 확인, 업무 분류와 담당 배정, 진행 상황 및 미결 사항 요약, 완료 보고 | 접수번호, 담당자, 현재 상태, 결정이 필요한 항목, 최종 결과 | 대표를 대신해 계약·결제·외부 발송·운영 변경을 독자 승인하지 않음 |
| Codex (운영 설계·품질 책임) | JKSTORY 업무 규칙 분석, 요구사항과 수용 기준 작성, 데이터 정합성·권한·감사 이력 검토, 결과 검증 및 개선 우선순위 결정 | 업무 설계, 검증 결과, 운영 위험과 수정안 | 검증되지 않은 수치나 AI 처리 결과를 확정값으로 보고하지 않음 |
| Claude Code (개발·기술 구현 책임) | 코드 구현, 테스트, 오류 수정, 연동 개발, 배포 절차 준비와 기술 문서화 | 변경 내역, 테스트 증거, 배포 상태와 복구 방법 | 구현 완료를 운영 검증 완료로 간주하지 않음 |
| Hermes (실행 조정·상태 관리 책임) | 허용된 도구로 작업을 실행하거나 연결된 에이전트의 상태를 수집하고, 작업 대기열·실패·재시도·일정을 관리 | 실행 로그, 성공·실패·보류 상태, 재시도 내역 | 연결되지 않은 서비스나 권한 밖 작업을 실행했다고 표시하지 않음 |

## 기본 업무 흐름

1. 대표가 전담비서에게 자연어로 지시합니다. 비서는 원문을 보존하고 업무 목적, 대상, 기한, 완료 기준을 구조화합니다.
2. 비서는 주담당을 한 명 지정합니다. 업무 규칙·분석·검증은 Codex, 코드·화면·연동은 Claude Code, 승인된 실행·상태 추적은 Hermes가 맡습니다. 복합 업무는 Codex가 수용 기준을 정하고 Claude Code가 구현하며 Hermes가 실행 상태를 추적합니다.
3. 작업자는 작업물과 근거를 기록합니다. Codex는 결과를 검토하고 미완료·오류·추가 결정 사항을 구분합니다.
4. 비서는 대표에게 결과, 실제 적용 여부, 다음 조치 한 가지를 요약합니다. 대표 승인이나 외부 서비스 권한이 필요한 단계는 해당 단계에서 명시합니다.

## 운영 전제와 단계

- 현재: 3D 공간에 세 AI의 시험 캐릭터가 있고, 브라우저 로컬에 저장되는 수동 업무판이 있습니다. 전담비서, 자동 배정, AI 사이 메시지 전달, 실제 실행은 구현 전입니다.
- 다음: 전담비서 접수 화면, 공용 업무 저장소, 권한과 감사 로그, 에이전트 연결 상태를 구현합니다. 먼저 개인정보 없는 가상 사례로 운영합니다.
- 이후: JKSTORY BPMS·WMS 등 실제 시스템은 API와 접근 권한, 테스트 환경, 승인 단계를 확인한 뒤 한 업무씩 연결합니다. 화면의 상태는 실제 실행 로그와 연결된 경우에만 `실행 중` 또는 `완료`로 표시합니다.

대표가 비서에게 보낼 지시 예시: “인천1센터 출고 요청 접수 과정을 시험해 줘. 누락되는 단계와 담당자를 찾고, 화면 수정이 필요하면 개발팀에 넘겨. 실제 출고 처리나 고객 발송은 하지 마.”
